# pretty-charts —— 高质量绘图技能

本技能是一棵**路由树**：先定性（画什么图、给谁看），再按 `routing.md` 的规则加载对应文件，最后逐项过清单自查。
**不要跳过第 1、2 步直接画图。**

## 设计哲学（一切规则的依据）

一张好图 = 读者在 5 秒内得到正确的信息，且不被形式干扰。
优先级 **准确 > 易读 > 简洁 > 美观**——任何与更高优先级冲突的美化都要舍弃。

1. **先删后加**：默认删掉一切不承载信息的元素（边框、网格线、图例框、3D、阴影），需要时再加回。
2. **墨水比**：每个元素问一句"删掉它信息会损失吗"，不会就删。
3. **一致**：同一交付物内所有图共用一套主题，且"语义 → 颜色"的映射全局一致（`spec/color.md` §5）。
4. **结构只定义一次**：横切规范（红线/取色/字体/尺寸/落盘）只在 `spec/` 定义，图型与工具文件只引用、不复述。

## 第 1 步：定性——先审内容，再定图型

**用户已指定图型** → 仍需走第 2 步定档（档位决定主题与自查清单），再进入第 3 步。

**用户只给了内容，没说画什么图** → 按顺序做完四件事，不要默默开画：

1. **一句话测试**：把内容压缩成"这张图要让读者 5 秒内得到 ______"。写不出 → 内容不适合画图，建议文字/表格。
2. **三分类探针**：把数字都删掉，句子还成立吗？成立 → **非数据图**；只剩数量关系还能看懂 → **数据图**；用数据讲结构化的故事 → **混合体**（按最终交付形态归类，两边规范都遵守）。
3. **选型**：读 [`references/selection.md`](references/selection.md)——数据图先定"要表达什么模式"，再看是否叠加空间/密集行列/不确定度等修饰维度；非数据图按拓扑类型选。
4. **输出推荐**：`推荐图型 + 理由（指向内容中的哪个特征）+ 备选 + 待确认的数据缺口`，经用户确认（或用户说"你看着办"）后进入第 2 步。推荐被否 = 核心信息提炼错了，回到第 1 项重来。

**诚实原则**（红线，详见 `spec/integrity.md` §3）：内容里没有数据不建议数据图，没有结构不建议流程图；只有结论没有数字时先要原始数据；**图注里出现的 n、置信区间、p 值必须由脚本真实计算，不得编造**。

## 第 2 步：定档——由输出介质判定

档位不是"学术/商务"这类社交标签，而是**输出介质的物理属性**：印刷（可能只有黑白）→ T1；屏幕文档逐字阅读 → T2；投影/远距离 → T3。

**三档定义、参数差异、工具选择、读取顺序与降级路径，统一见 [`references/routing.md`](references/routing.md)（唯一定义处）。** 用户已说明档位则遵从；仍不确定就问一句，不要猜。

## 第 3 步：按 routing.md §3 加载文件后作图

`routing.md` §3 给出唯一规则：图型专属文件 + 工具专属文件 + `spec/` 横切规范。三类文件的关系是：

- **图型专属**：`references/data/<目的>.md`（比较/分布/构成/趋势/关系/网络/地理/热图/统计）或 `references/diagram/<图型>.md`（流程与时序/架构/层级/示意/信息图）——只讲该图型的取舍与陷阱。
- **工具专属**：`references/data/tool-{matplotlib,echarts}.md`、`references/diagram/tool-{tikz,graphviz,svg}.md`——只讲该工具栈的 API 与坑。
- **横切规范**：`references/spec/{integrity,color,type,layout,diagram}.md`——红线、取色、字体、尺寸落盘、非数据图布局。**只在这里定义一次。**

**代码必须显式加载主题资产**（如 `plt.style.use(...academic.mplstyle)`），**禁止硬编码样式常量**（色值、字号、线宽、DPI、figsize）。

非数据图交付级一律 TikZ，**不使用 mermaid**：流程图用 `references/style/tikz/flowchart-styles.tex`，时序图用 `sequence-styles.tex`，二者均为 `\pcPaperMode`/`\pcPPTMode` 双模式。注意**模式宏只切配色、线宽、字号，不含字体**——字体要自己用 `\setmainfont`/`\setCJKmainfont` 声明（`spec/type.md` §1）。

## 第 4 步：交付

交付说明必须写明三项（都可核验）：

1. 所用**档位与主题**（如 academic / T1）；
2. **导出规格**（矢量或 DPI、成品尺寸）；
3. [`references/checklist.md`](references/checklist.md) 对应档位的**逐项结论**。

> 早期版本还要求列出"已读文件列表"。该项不可核验、白占输出预算，已移除；防跳步由"第 2 步定档 → 第 3 步按 routing.md 加载 → 第 4 步清单结论"承担。

**环境缺失时不要默默出不合规的图**：无 XeLaTeX、缺中文字体、只能出位图等情况，按 [`routing.md`](references/routing.md) §5 的降级路径处理，并在交付说明里写明降级了什么。
