# pretty-charts

五步：定性（画什么）→ 定档（给谁看）→ 作图 → 目检 → 交付。每步只读本步决策所需的文件：选型读 select，定档查表，作图才读规范——不通读 `references/`。第 1、2 步的全部决定落盘为 chart-plan.md，后面每一步对照它执行。

## 设计原则

一张好图 = 读者 5 秒内得到正确的信息，且不被形式干扰。优先级：准确 > 易读 > 简洁 > 美观。

1. **先删后加**：默认删除不承载信息的元素（边框、网格线、图例框、3D、阴影），需要时再加。
2. **墨水比**：每个元素问一句"删掉它信息会损失吗"，不会就删。
3. **一致**：同一交付物内所有图共用一套主题与一套"语义 → 颜色"映射。

## 第 1 步：定性

**先看数据再判断**：规模、缺失、类别数、时间粒度——下面每条判断的事实依据都来自这里。

**再做三条判断。用户已指定图型也要做。**

1. **一句话测试**。把内容压缩成"这张图要让读者 5 秒内得到 ______"。写不出，就建议改用文字或表格。
2. **三分类分流**。把数字删掉，句子还成立 → 非数据图；只剩数量关系还能读懂 → 数据图；用数据讲结构化故事 → 混合体（按最终交付形态归类，两边规范都遵守）。这一步决定后面按数据图的规范还是非数据图的规范来做。
3. **该不该画**。没有数据不画数据图，没有结构不画流程图；只有结论没有数字时先要原始数据。

分流之后：

- **用户已指定图型** → 跳过选型，进第 2 步。
- **只给了内容** → 读 `references/select.md` 选型：目的 → 家族、跨家族对照表、非数据图拓扑选型、归属判定。

最后**输出推荐**：推荐图型 + 理由（指向内容中的哪个特征）+ 备选 + 待确认的数据缺口。用户在线就等确认，再进第 2 步；**无人值守或任务要求一次交付时，按推荐直接执行，并把备选写进 chart-plan.md**。推荐被否说明核心信息提炼错了，回第 1 条重来。

本步产出：图型 + 备选 + 数据缺口。

## 第 2 步：定档

档位由输出介质决定。用户已说明档位则遵从；不确定且用户在线就问，不要猜；**无人值守（用户不在线、任务要求一次交付）按第一列推断**，都对不上取 T2 并在交付说明里写明"档位是推断的"。本步只决定档位与色板，不读文件、不加载资产——那些都是第 3 步的事。

| 语境线索（用户的话 / 任务特征） | 介质 | 档位 | 色板 |
|---|---|---|---|
| 论文 / 学位论文 / 期刊投稿 | 印刷，可能只有黑白 | T1 出版级 | academic |
| 报告 / Word·PDF 文档 / 网页与邮件配图 | 屏幕文档，逐字阅读 | T2 报告级（默认） | business |
| PPT / 海报 / 大屏 | 投影、远距离、一屏一结论 | T3 展示级 | showcase |

**本步收尾 = 写出 chart-plan.md**：

1. 新建本任务交付目录 `<项目>/figures/<任务名>/`，chart-plan.md 写在其中，图与脚本随后都落这里；历史任务的交付目录只读不碰。
2. 内容 = 第 1、2 步的全部决定，头部必须有任务名与日期，按此模板填：

   ```markdown
   # chart-plan —— <任务名>（<日期>）
   1. 一句话测试：这张图要让读者 5 秒内得到 ______
   2. 分流：数据图 / 非数据图 / 混合
   3. 选型：图型 + 理由 + 备选（用户已指定图型则写明）
   4. 档位与色板：T? / <色板名> —— 依据：用户指定 / 语境推断（无人值守推断的要声明）
   5. TikZ 片段：要 `\input` 的片段（preamble / 模式宏 / 字体）；数据图任务写"无"（资产文件名 = 色板名）
   6. 语义→颜色：语义 = token（hex）；多图交付一次分配、全局复用
   7. 数据缺口：待确认项；无则写"无"
   ```
3. 只记本任务的决定，不复述任何通用规范。

本步不查规范文档（`common.md`、`tools/` 留到第 3 步）；字号、线宽、DPI、画布等数值参数，以及主题资产的加载，都在第 3 步。

本步产出：档位与色板 + 交付目录内的 chart-plan.md。同一交付物内所有图同档同色板。

## 第 3 步：作图

四个动作按序：**回读 → 备料 → 装配 → 作画**。

**① 回读**——打开 chart-plan.md 核对头部：任务名与日期须与本任务一致，不一致则停下核对交付目录；没有 plan 就先完成第 1、2 步。

**② 备料**——按序读四份材料，读什么由 chart-plan 里的两个决定给出：

第一份，公共规则（恒读）：`references/common.md`——红线 / 取色 / 字体 / 尺寸落盘，一次读完。

第二份，图型方法论——由第 1 步的图型决定：

| 要画的图型 | 规范文件 |
|---|---|
| 条形 / 柱状 / 分组柱 / 堆叠 / 100% 堆叠 / 点图 / 哑铃 / 斜率 / 饼 / 环 / 瀑布 / 雷达（慎用） | `charts/compare.md` |
| 折线 / 面积 / 堆叠面积 / 日历热图 | `charts/trend.md` |
| 直方 / KDE / 箱线 / 小提琴 / ECDF / 山脊 | `charts/distribution.md` |
| 散点 / 气泡 / 二维密度 / hexbin / 相关矩阵 / 热图 | `charts/relationship.md` |
| 树图 / 桑基 / 弦图 / 力导向 / 河流图 | `charts/structure.md` |
| choropleth / 比例符号 / 小倍数地图 | `charts/map.md` |
| 误差棒 / 置信区间 / 显著性 / 森林图，叠加到上表任一族 | `charts/inference.md` |
| 流程图 / 时序图 / 状态图 / 甘特图 / 架构图 / 思维导图 / 示意图 / 信息图 | `diagrams.md` |

第三份，工具文件——由第 2 步的交付形态决定：

| 交付形态 | 工具文件 |
|---|---|
| 数据图 · 静态出图（PPT / 海报位图也是静态） | `tools/python.md` |
| 数据图 · 网页或交互（大屏、可交互报告） | `tools/web.md` |
| 非数据图（交付级 TikZ） | `tools/tex.md` |

第四份，相近示例：`examples/INDEX.md` 找同图型的脚本与成图，照着改。

**③ 装配**——第 2 步定下的色板名在这里兑现成文件，**资产文件名 = 色板名**：

- matplotlib：`references/assets/matplotlib/<色板>.mplstyle`
- 网页交付：`references/assets/echarts/<色板>.json`
- TikZ：按 chart-plan 第 5 项 `\input` 对应片段

取色只从 `references/assets/palettes/<色板>.json` 取，语义 → 颜色按 chart-plan 的分配执行，不许各图自取 `categorical[0]`。**禁止硬编码样式常量**（色值、字号、线宽、DPI、figsize）。

**④ 作画**——按图型方法论文档与工具文件执行，全程守红线。非数据图交付级用 TikZ、不用 mermaid；`\pcPaperMode` / `\pcPPTMode` 只切配色、线宽、字号，字体方案见 `common.md`「字体与文字」。画完即进第 4 步目检。

**回炉**——作图中发现数据形状与选型假设不符（类别超限、分布形态意外、缺失面超预期）：回第 1 步重定性、第 2 步重定档，**整体重写** chart-plan.md（不追加），再回来继续。

## 第 4 步：目检

渲染成图（TikZ 则编译出 PDF），**打开图片逐项看**——不许看着代码勾清单。本步最多三轮"修改 → 重渲染"，三轮后仍有问题就如实报告交付，不无限打磨。

**第一遍先枚举、后评价**：列出你看到的标题、轴标签、图例、标注、数据编码，再逐项核对——

1. **语义保真**：画的确实是用户要的东西？标题与内容相符？画对了列与量纲？
2. **数据完整性**：轴范围合理？柱状从 0 起（红线）？该有的参考线、误差表示在？
3. **设计原则抽查**：语义 → 颜色与 chart-plan 一致？关键结论有标注（不只是轴）？颜色之外有第二编码（线型/标记/标签）？
4. **版面**：标签与标注无重叠、无裁切（中文字、长类别名、密集刻度最易出事）；图例不压数据；按目标渠道缩放后文字仍可读。
5. **指出一个改进点**——哪怕整体已合格。

有问题 → 回第 3 步修改并重渲染（计入轮次）；无问题 → 进第 5 步。

## 第 5 步：交付

交付说明写四项：档位与主题（推断的要声明）、导出规格（矢量或 DPI、成品尺寸）、过程证据（目检已通过、chart-plan 未漂移）、下列清单的逐项结论。

### 三档通用

- [ ] 九条红线无违反（`common.md`「红线与诚实原则」）
- [ ] 颜色全部来自所选色板 JSON；语义 → 颜色映射与 chart-plan 一致（多图交付尤须全局一致）
- [ ] 字号达到本档下限，按缩放后的等效字号判断（`common.md`「字体与文字」）
- [ ] 矢量优先，DPI 与尺寸符合目标渠道（`common.md`「画布、尺寸、导出与落盘」）
- [ ] 图与 chart-plan 同在交付目录，命名规范，无中间产物残留
- [ ] 无障碍四项通过（`common.md`「无障碍」：第二编码 / 对比度 / alt 文本 / 字号下限）
- [ ] 图注自含 n、统计口径、误差类型、显著性定义、数据来源

### T1 出版级

- [ ] 图型与分析目的匹配，选型依据可陈述
- [ ] 尺寸等于目标期刊栏宽（90 / 190mm，或按期刊模板实测）；精确栏宽时不用 tight bbox
- [ ] 配色全部来自 academic 色板；TikZ 论文版黑白灰单色属合规特例
- [ ] 灰度打印仍可分辨
- [ ] 误差棒或 CI 齐全，图注含 n、统计检验、显著性标注规范
- [ ] 轴有单位，量级用科学记数或 SI 词头，不出现 `1e6` 这类裸记数
- [ ] XeLaTeX 不嵌可变字体；经 Ghostscript 管线时换静态字体（`common.md`「字体与文字」）
- [ ] 导出矢量 PDF + 600dpi 兜底 PNG，`pdf.fonttype 42`

### T2 报告级

- [ ] 标题或副标题说结论与口径，如"Q3 华南区增速第一（+34% YoY）"
- [ ] 关键数据直接标注，读者不必比对网格线
- [ ] 配色来自 business 色板；重要系列用主色，对照用 `neutral`
- [ ] 数字口径、单位、时间范围在图内可追溯
- [ ] 柱状 y 轴从 0，无违规双轴
- [ ] 200dpi PNG 或 SVG，嵌入文档后文字仍 ≥9pt

### T3 展示级

- [ ] 一页一结论，删掉与结论无关的系列
- [ ] 最后一排观众可读：字号 ≥11pt 等效，线宽 ≥2pt
- [ ] 直接标注放在数据旁，不用小图例
- [ ] 配色来自 showcase 色板，与页面模板不冲突，深色背景下检查对比度
- [ ] ECharts 只用入场动画，不用旋转 3D
- [ ] 导出尺寸等于插入位置，不缩放位图

### 环境缺失

**降级是显式决定，不默默出图**：环境缺什么，就在交付说明里写明降级了什么。唯一的用户决策点：TikZ 编译不了（先用 `xelatex --version` 确认）——问用户装 TeX 发行版，或降级为 matplotlib 手绘示意图、产物标注"非交付级"。其余缺失的处理在各自规范里：中文字体与 Linux 字体包见 `common.md`「字体与文字」，位图 DPI 见「画布、尺寸、导出与落盘」§2，地图底图的仓库自带数据见 `charts/map.md`。
