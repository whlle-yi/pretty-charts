# 内容审读与选型入口（content-analysis）

> 当用户给出一段内容（文字、数据表、描述、笔记）而**未指定图型**时，从本文件开始。产出：推荐图型 + 理由 + 备选，然后进入 `data/chart-selection.md` 或 `diagram/diagram-selection.md` 的常规流程。

## 第 1 步：析出核心信息（一句话测试）

把内容压缩成一句话：**"这张图要让读者在 5 秒内得到 ______。"**

- 写不出这句话 → 内容信息密度不足或过于零散，**建议不画图**：改用文字、列表或表格（三个数字以内直接写进句子）。
- 能写出 → 这句话里的**谓语动词**就是选型线索：谁比谁大（比较）、怎么变的（趋势）、占多少（构成）、怎么分布（分布）、有无关联（关系）、怎么流转（流程）、怎么归类（层级）。

## 第 2 步：内容三分类

| 内容形态 | 判据 | 去向 |
|---|---|---|
| **含数值数据** | 有可数的量：数字、百分比、时间序列、统计量 | `data/chart-selection.md` 决策树 |
| **表达结构/过程** | 有步骤、分支、层级、组成、依赖、流转 | `diagram/diagram-selection.md` 决策树 |
| **混合体** | 用数据讲一个结构化的故事 | 按主体定性（通常是数据图），结构部分另配小图 |

分不清时的两个探针问题：**把数字都删掉，句子还成立吗？** 成立 → 非数据图。**把名词都删掉只剩数量关系，还能看懂吗？** 能 → 数据图。

## 第 3 步：内容特征 → 图型速查

数据侧：

| 内容特征 | 首选 |
|---|---|
| 若干类别 + 一个数量（"谁多谁少"） | 排序条形图 |
| 同一指标沿时间变化 | 折线图 |
| 整体与占比（≤5 块） | 环图；>5 块或随时间 → 堆叠柱 |
| 两组数据的分布差异 | 箱线/小提琴 + 散点 |
| 两个量的关联 | 散点 + 回归带 |
| 行×列密集数值 | 热图 |
| 空间位置上的差异 | 地图（choropleth/比例符号） |
| 强调单个关键数字 | 大数字块（不画图） |

结构侧：

| 内容特征 | 首选 |
|---|---|
| 有先后顺序、有分支判断 | 流程图 |
| 多方交互、有来有回 | 时序图 |
| 任务有排期和依赖 | 甘特图 |
| 从属归类、发散梳理 | 思维导图 |
| 系统组成与依赖 | 分层架构图 |
| 原理/机制解释 | 示意图（TikZ） |

## 第 4 步：推荐输出格式（对用户的答复）

按此格式给出推荐，**不要默默开画**：

```
推荐：<图型> —— 理由：<一句话，指向内容中的哪个特征>
备选：<次选图型>（<何时改用它>）
待确认：<数据缺口 / 口径问题 / 是否有原始数据>
```

- 用户确认或说"你看着办" → 按推荐进入 `scenarios.md` 对应档位，走常规流程。
- 推荐被否 → 换备选并追问原因（通常是核心信息一句话提炼错了）。

## 诚实原则

- 内容里**没有数据**时不要建议数据图；**没有结构**时不要建议流程图。
- 原始数据缺失（只有结论没有数字）→ 先向用户要数据，或改画结构图。
- 两种图型难分伯仲时，选**信息损耗更小**的一种。
