# 流程与时序（flowchart）

> 覆盖：流程图、时序图、状态图、甘特图。主力工具 mermaid（`tool-mermaid.md`），复杂布局退到 Graphviz。

## 1. 流程图（flowchart）

**何时用**：步骤有分支/循环/并行；审批流、算法逻辑、业务流程。

规范：
1. 方向单一：TD（上到下）适合窄页面与文档，LR（左到右）适合宽屏与 PPT；同一交付物统一。
2. 判断节点用菱形，**每个分支出口必须标条件**；布尔条件用"是/否"。
3. 起止节点用圆角矩形（`([...])`），处理用矩形，输入输出用平行四边形，数据库用圆柱。
4. 回流（循环）箭头绕主线外侧、加虚线或标条件，不横穿其他节点。
5. 节点 ≤20 个：超了就分层——先画一级主流程，子流程另画一张并引用（`subgraph` 或独立图）。
6. 泳道（跨角色职责）：mermaid 用 `subgraph` 按角色分块；角色 >3 时考虑时序图代替。
7. 连线标签直接写条件文字（`-->|是|`），不要图例集合。

常见错误：❌ 箭头无标签的判断分支；❌ 流程线交叉成蜘蛛网（重排布局或拆图）；❌ 节点里写整段话。

## 2. 时序图（sequenceDiagram）

**何时用**：多角色/多系统之间的交互顺序（API 调用、协议握手）。

规范：
1. 参与者 ≤6 个：超了按子系统拆图。
2. 消息动词开头："请求/返回/推送"；返回值用 `-->>` 虚线，与请求实线区分。
3. 条件块（alt/else）、循环（loop）必须有标签说明条件。
4. 异步消息标明（`-)` vs `->>`）。
5. 编号：步骤需要被引用时开启 autonumber。

## 3. 状态图（stateDiagram-v2）

**何时用**：对象生命周期（订单状态、连接状态）。状态 ≤10；非法/异常状态别省略（它们往往才是设计重点）；转移线上写触发事件。

## 4. 甘特图（gantt）

**何时用**：项目排期、任务依赖与时间线。

规范：
1. 任务按阶段分组（section），单屏任务 ≤15 个，超了按阶段拆图。
2. 关键路径/里程碑：milestone 语法单独标出；交付节点必须可见。
3. 任务日期.todayOffset 不用相对猜测，明确写起止或工期。
4. 依赖（after）显式声明，不要用日期对齐暗示。
